# 11 · Click map: what every click does

As of 30 Sep 2026 (IST). One row per interactive element on every page, in page order: 264 rows. Each row says
what the element is, where it sits, what triggers it, what happens in the real app (route and URL params, UI change),
which hook, endpoint, Epoch instruction or wallet call it uses, and its loading, empty, error and success states.

**How to use it.** Build a page with its board open on the design canvas (press Play: every link, tab, button and flow
works) and this file beside it. Treat every row as a test case: when a page is done, each of its rows should pass in
Playwright. If the real app needs something a row doesn't cover, add a row, never guess.

**Row prefixes:** SH app shell · LA landing · TE terminal · VE validators explorer · VP validator profile + Manage ·
MS My Stake (sign-in and Predict included) · VA vault. Canvas boards: `Main`, `Terminal`, `Validators`, `Validator`,
`MyStake`, `Vault`.

**Prototype-only controls (do not build):** the "Viewing as: Public · Operator (demo)" switch and the demo state switch on
the validator profile; the dashed "Prototype" rows in the wallet steps on My Stake (wallet approves / rejects / Devnet);
"Skip ahead 3 epochs (demo)" and "Start the demo over". They exist so every state can be reached on the canvas.

**Words.** Advance, borrow, sweep, bond, tranche (Senior, Junior), target (never "guaranteed"), share price, Fee Index.
Predict: call, market, pool, payout (never bet, gamble, wager, odds). A missing value is "—", never 0.
